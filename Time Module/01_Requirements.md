# Time Module – Requirements

## 1. Module Overview

The Time module allows employees and authorized users to manage,
record, review, and monitor employee working time, attendance,
timesheets, and related activities.

## 2. Objective

The objective of testing the Time module is to verify that users can
correctly record, view, search, and manage time-related information.

## 3. Functional Requirements

### FR-TIME-001 – Time Navigation

The system shall allow authorized users to open the Time module.

### FR-TIME-002 – Time Page

The system shall display the appropriate Time page and available
time-management options.

### FR-TIME-003 – Timesheet

The system shall allow eligible users to access their timesheet.

### FR-TIME-004 – Select Employee

Authorized users shall be able to select an employee where applicable.

### FR-TIME-005 – Select Date

The system shall allow users to select the appropriate timesheet period
or date.

### FR-TIME-006 – Add Timesheet Entry

The system shall allow users to add time entries to a timesheet.

### FR-TIME-007 – Project Selection

The system shall allow users to select an available project.

### FR-TIME-008 – Activity Selection

The system shall allow users to select an appropriate activity.

### FR-TIME-009 – Enter Hours

The system shall allow users to enter valid working hours.

### FR-TIME-010 – Save Timesheet

The system shall allow valid timesheet information to be saved.

### FR-TIME-011 – Submit Timesheet

The system shall allow users to submit a completed timesheet where applicable.

### FR-TIME-012 – View Timesheet

Users shall be able to view previously entered timesheet information.

### FR-TIME-013 – Edit Timesheet

Users shall be able to edit eligible timesheet information.

### FR-TIME-014 – Delete Timesheet Entry

Users shall be able to delete eligible timesheet entries.

### FR-TIME-015 – Search Records

Authorized users shall be able to search/filter time records.

### FR-TIME-016 – Validation

The system shall validate required fields and invalid time information.

### FR-TIME-017 – Authorization

Restricted time-management operations shall only be available to
authorized users.

## 4. Non-Functional Requirements

### NFR-TIME-001 – Usability

The Time module should be easy to navigate and understand.

### NFR-TIME-002 – Performance

Time records and timesheet operations should respond within an
acceptable time.

### NFR-TIME-003 – Security

Time and attendance information should only be accessible to authorized users.

### NFR-TIME-004 – Compatibility

The Time module should work correctly on supported browsers.

### NFR-TIME-005 – Reliability

Timesheet information should be saved and retrieved reliably.

## 5. Testing Scope

Testing will cover:

- Functional Testing
- Positive Testing
- Negative Testing
- Validation Testing
- UI Testing
- Workflow Testing
- Authorization Testing
- Security Testing
- Compatibility Testing
- Performance Testing
- Exploratory Testing
- Regression Testing
- Smoke Testing
- Sanity Testing

## 6. Out of Scope

Third-party integrations and functionality outside the Time module are
outside the primary scope unless required for integration or system testing.
